# Medical Sign — מערכת שילוט דיגיטלי לבית חולים

Digital signage for a hospital: manage departments, rooms, doctors and shifts in one place —
every screen by every door updates itself instantly. No more printing and swapping paper signs.

Runs on plain Node.js with **no npm packages at all**, so it works offline on any hospital PC.

---

## הפעלה / Running

```bash
npm start
```

Then open:

| מה | כתובת |
|---|---|
| ממשק הניהול / Admin | `http://localhost:3000/` |
| שלט דלת / A door screen | `http://localhost:3000/display.html?room=201` |
| מדריך קומה / A floor directory | `http://localhost:3000/display.html?floor=2` |

The console also prints a **network address** (e.g. `http://10.0.0.16:3000/`).
That is the address to open on the screens and tablets around the building — they all
talk to this one PC.

### משתמשים וקודי גישה

לכל אדם יש **קוד אישי משלו**. אין קוד משותף לצוות.

**הרשמה** — בעמוד הכניסה יש לשונית "הרשמה". ממלאים שם מלא, טלפון ותעודת זהות
(מאומתת בספרת ביקורת), ומקבלים מיד קוד אישי בן 6 ספרות.
הקוד מוצג **פעם אחת בלבד** — הוא נשמר מוצפן (scrypt) ולא ניתן לשחזור.
אם קוד אובד, מנהל מנפיק חדש והישן מפסיק לעבוד מיד.

**אישור** — חשבון חדש נפתח בסטטוס "ממתין לאישור": אפשר להיכנס, אבל אי אפשר
לראות נתונים או לשנות שילוט עד שמנהל מאשר.
בקשות ממתינות מופיעות בשני מקומות: בכרטיס "בקשות הצטרפות" במסך הסקירה
(עם כפתורי אישור והשעיה במקום), ובמסך "משתמשים" תחת "ממתינים לאישור" —
מסומן בצהוב, עם מונה אדום בתפריט הצד. כל מנהל יכול לאשר, לא רק בעל קוד הגיבוי.

מי שממתין לאישור רואה מסך המתנה שמקשיב לשרת: **ברגע שמנהל מאשר אותו הוא נכנס
מיד, בלי לרענן את הדף ובלי להזין את הקוד שוב.** אותו מנגנון פועל גם בכיוון ההפוך —
משתמש שהושעה או נמחק בזמן שהוא מחובר מוחזר מיד למסך הכניסה. כך אדם זר שמגיע לרשת של בית החולים
לא יכול לרשום את עצמו ולערוך שלטים.

| רמה | מה רואה | מה מותר לשנות |
|---|---|---|
| **צוות** (ברירת מחדל) | הודעות, רופאים, יומן שלי, והחשבון האישי בהגדרות | **רק הודעות שהוא עצמו כתב.** רופאים לצפייה בלבד. יומן השינויים אינו זמין לו כלל |
| **מנהל** | הכל: סקירה, מחלקות, חדרים, שיבוצים, שלטים, משתמשים | כל נתוני השילוט, אישור והשעיה של משתמשים, שם בית החולים, גיבוי |
| **קוד גיבוי** ("מנהל מערכת" — חשבון מובנה, ללא הרשמה) | הכל, כולל תיבת דואר משלו | בנוסף: מינוי מנהלים, הנפקת קודים, מחיקת משתמשים, שינוי הקודים |

כל הודעה נושאת את שם הכותב, ובטבלה מופיעה עמודת "נכתב על ידי".
חשבון צוות רואה את כל ההודעות, אבל כפתורי עריכה ומחיקה מופיעים רק בשורות שלו —
בשאר השורות כתוב "נכתב על ידי אחר". מנהל יכול לערוך ולמחוק כל הודעה.
הודעות ישנות שנוצרו לפני שהמערכת התחילה לתעד כותב אינן ניתנות לעריכה על ידי צוות.

חשוב: ההגבלה נאכפת **בשרת**, לא רק בתפריט. חשבון צוות שינסה לשנות רופא, חדר,
מחלקה, שיבוץ או שלט יקבל שגיאת הרשאה, גם אם יעקוף את הממשק.
נתוני שיבוצים, שלטים ויומן השינויים אפילו לא נשלחים לדפדפן של חשבון צוות.

**קוד הגיבוי (מנהל־על)** — כניסה עם הקוד הזה היא **חשבון מובנה בשם "מנהל מערכת"**:
מנהל מלא בלי הרשמה, בלי שם, טלפון או תעודת זהות. יש לו הרשאות לכל דבר במערכת,
כולל תיבת דואר משלו — אפשר לשלוח אליו בקשות ולקבל ממנו תשובות, בדיוק כמו לכל אדם.
במסך ההגדרות הוא מציג כרטיס שמסביר מה מותר לו במקום כרטיס חשבון אישי.

שימו לב: זהו קוד משותף ולא אדם. כל פעולה שנעשית איתו נרשמת ביומן בשם "מנהל מערכת"
ולא על שם מי שביצע אותה — לכן לעבודה יומיומית עדיף חשבון אישי, ואת קוד הגיבוי
שומרים למקרי חירום ולניהול הקודים.

הקוד נוצר אוטומטית בהפעלה הראשונה, מוצג בחלון השרת
ונשמר ב-`data/MASTER-CODE.txt`. הוא:

* **נדרש כדי לשנות את קוד הכניסה** — כך אף אחד לא יכול לנעול אתכם בחוץ.
* **מאפשר כניסה תמיד**, גם אם כל שאר הקודים אבדו.
* **לא נשלח לדפדפן לעולם** ולא מופיע בגיבויים (הקודים מוחלפים ב-`(redacted)`).

**החשבון שלי** — במסך "הגדרות" כל משתמש רואה בראש העמוד כרטיס עם הפרטים שלו:
ארבע ספרות אחרונות של תעודת הזהות, תאריך הרשמה, כניסה אחרונה ומי אישר אותו, וכן הסטטוס וההרשאה.
משם אפשר לעדכן שם וטלפון, ולבחור קוד אישי חדש (מזינים את הקוד הנוכחי ואת החדש פעמיים).
לא ניתן לשנות דרך המסך הזה תעודת זהות, הרשאה או סטטוס — אלה בידי מנהל בלבד.
קוד חדש שנבחר נבדק מול כל שאר הקודים במערכת, כדי שלא יהיו שתי כניסות עם אותו קוד.
צוות רואה במסך ההגדרות רק את הכרטיס האישי; שם בית החולים וקודי הגישה מוצגים למנהלים בלבד.

**פרטיות — תעודת הזהות אינה נשמרת** — בהרשמה המערכת בודקת שהמספר תקין ושאין כבר
משתמש איתו, ומיד אחר כך מוחקת אותו. נשמרים רק טביעה מוצפנת (scrypt) וארבע הספרות
האחרונות, כך שהתצוגה בכל מקום היא `•••••6782` ואי אפשר לשחזר את המספר — לא מנהל,
לא קוד הגיבוי ולא מתוך `data/db.json`. זהו יישום של עקרון צמצום המידע בחוק הגנת
הפרטיות: שומרים רק את מה שבאמת נדרש.

מסד נתונים מגרסה קודמת, שבו המספרים עדיין שמורים במלואם, מומר אוטומטית בהפעלה
הראשונה אחרי העדכון — ההמרה חד־כיוונית ומודפסת לקונסולה.

**תיעוד** — כל שינוי נרשם ביומן עם השם של מי שביצע אותו, וגם כל כניסה למערכת.
אחרי 8 ניסיונות כניסה שגויים הכתובת נחסמת לדקה.

### להריץ את המערכת על שרת (ולא רק במחשב אחד)

יש שתי גרסאות, וחשוב לא לבלבל ביניהן:

| | נשמר? | מי יכול להיכנס |
|---|---|---|
| **ההדגמה** (`docs/`, Netlify) | לא — מתאפסת בכל רענון | כל אחד, בלי קוד |
| **המערכת** (`server.js`) | כן — `data/db.json` | רק קוד אישי מאושר |

ההדגמה היא חלון ראווה. Netlify מגיש קבצים סטטיים בלבד ולכן אינו יכול
להריץ את השרת — ולכן שם אין זיכרון ואין מנעול.

כדי שהמערכת האמיתית תהיה זמינה מכל מקום צריך אירוח שמריץ Node.
בקובץ `render.yaml` יש הגדרה מוכנה ל-Render.

**הדבר היחיד שחייבים להבין לפני העלאה:** בשרת מתארח, תיקיית האפליקציה
נמחקת בכל פריסה מחדש. לכן מסד הנתונים חייב לשבת על דיסק מחובר ששורד —
מגדירים את `MEDSIGN_DATA_DIR` לנתיב שלו:

```
MEDSIGN_DATA_DIR=/var/medsign-data
```

בלי זה המערכת תעבוד — ותאבד הכול בכל עדכון. בהרצה מקומית אין מה להגדיר:
הנתונים יושבים ב-`data/` ליד הקוד, כרגיל.

### מסמכים ומדיניות

במסך "הגדרות" — אצל כל משתמש, צוות ומנהלים כאחד — יש כרטיס עם שלושה מסמכים:
**מדיניות פרטיות**, **תנאי שימוש** ו**הצהרת נגישות**. לכל מסמך יש כפתור הדפסה
שפותח אותו כעמוד נפרד, מעוצב להדפסה או לשמירה כ-PDF — זה מה שמגישים לגורם רכש
שמבקש את מדיניות הפרטיות כמסמך.

המסמכים נבנים ב-`lib/legal.js` מתוך ההגדרות החיות (שם בית החולים, טלפון לפניות),
כדי שלא ייווצר מצב שבו המסמך מתאר מערכת אחרת ממה שרץ בפועל. הם מוגשים דרך
`GET /api/legal` — הנתיב הזה **אינו** דורש קוד, בכוונה: מי שעומד להזין תעודת זהות
בטופס ההרשמה צריך להיות מסוגל לקרוא קודם מה נשמר עליו. לכן יש גם קישורים אליהם
בתחתית מסך הכניסה.

**אין באנר עוגיות, ובכוונה.** האתר אינו מגדיר עוגיות כלל ואינו טוען דבר מאתר
חיצוני — אין מעקב, אין אנליטיקס ואין גופנים מרוחקים. מה שכן נשמר בדפדפן הוא שלושה
פריטים תפעוליים (`medsign.lang`, `medsign.view`, `medsign.pin`), והם מתוארים בתוך
מדיניות הפרטיות. באנר אישור מעל שום מעקב היה מקפיץ חלונית בכל טאבלט ליד כל דלת,
כמה פעמים ביום, בלי להגן על אף אחד.

המסמכים נכתבו כטקסט בשפה פשוטה, ואינם ייעוץ משפטי. לפני מכירה או הטמעה כדאי
שיעברו אצל היועץ המשפטי וממונה הגנת הפרטיות של בית החולים.

### נגישות

הממשק נבנה לפי ת"י 5568 ברמה AA: ניווט מלא במקלדת עם סימון מיקוד ברור, קישור
"דילוג לתוכן", תוויות מילוליות לכל כפתור אייקון, `aria-hidden` על סמלים דקורטיביים,
הכרזות `aria-live` על הודעות מערכת, מבנה כותרות תקין, ותמיכה ב-`prefers-reduced-motion`.
ההצהרה במסך ההגדרות מפרטת גם את המגבלות הידועות — היא נכתבה כדי לומר את האמת על
מה שנבדק ומה שלא, ולא כדי להצהיר על התאמה מלאה.

### יומן שלי — תיבת דואר פנימית

לכל בעל חשבון אישי יש תיבת דואר: אנשי הצוות שולחים זה לזה בקשות, משימות ועדכונים
("נא לעדכן את שלט 231", "הסי.טי חזר לפעילות").

* **דואר נכנס / נשלחו** — שתי לשוניות, עם מונה אדום של הודעות שלא נקראו בתפריט הצד.
* פתיחת הודעה מסמנת אותה כנקראה. אפשר **להשיב**, לסמן **בוצע** (מסומן ב-✓ וקו חוצה),
  או למחוק. **רק הנמען** יכול לסמן נקרא/בוצע.
* **מחיקה היא חד-צדדית** — היא מסירה את ההודעה מהתיבה שלך בלבד; אצל הצד השני היא נשארת.
* אף אחד מלבד השולח והנמען לא רואה את ההודעה, גם לא מנהל.
* רשימת הנמענים כוללת שמות בלבד — לא טלפונים ולא תעודות זהות.
* לקוד הגיבוי יש תיבת דואר בשם **"מנהל מערכת"** — כל אחד יכול לשלוח אליה בקשה,
  והיא יכולה להשיב. לקוד המשותף אין תיבה, כי הוא אנונימי ואי אפשר לדעת למי להעביר.

### הדגמה ציבורית (GitHub Pages)

התיקייה `docs/` היא **גרסת הדגמה** של אותה מערכת, שרצה ללא שרת כלל.
היא נועדה להצגה: אפשר לשלוח קישור לבית החולים והם יתנסו במערכת מהדפדפן,
בלי להתקין כלום ובלי גישה לנתונים אמיתיים.

* `docs/demo.js` מחליף את השרת — הוא תופס את קריאות ה-API ועונה עליהן
  מתוך נתוני דוגמה שמוטמעים בדפדפן.
* **כל קוד** פותח את ההדגמה כמנהל, כדי שאפשר יהיה לראות את כל המסכים.
* שינויים נשמרים בזיכרון הדפדפן בלבד ונמחקים ברענון. אין שם מידע אמיתי.
* פס כהה בראש העמוד מבהיר שזו הדגמה.

**להפעלה:** ב-GitHub → Settings → Pages → Source: `main` ותיקייה `/docs`.
הכתובת תהיה `https://<שם-המשתמש>.github.io/<שם-המאגר>/`.

חשוב: **הגרסה האמיתית לא יכולה לרוץ ב-GitHub Pages.** Pages מגיש קבצים
סטטיים בלבד, בלי Node ובלי בסיס נתונים — ולכן המערכת האמיתית מורצת
במחשב של בית החולים (`npm start`), והמסכים פונים אליו ברשת המקומית.

## איך זה עובד / How it works

1. **מחלקות** — שם, קומה, אגף, צבע זיהוי, טלפון, שעות קבלה.
2. **חדרים** — מספר, שם, מחלקה, סטטוס (פתוח / סגור / בהפסקה / חירום) והערה שמוצגת על השלט.
3. **רופאים** — שם, תואר, התמחות, מחלקה, **טלפון משרד** ומספר רישיון.
   בטבלה יש עמודת **"נמצא כעת"** שמראה באיזה חדר ובאיזו קומה הרופא יושב ברגע זה
   (למשל "201 · קומה 2" עם שעות המשמרת), ומקף כשאינו נמצא בחדר.
   העמודה מתעדכנת מהשרת אחת לדקה. גם חשבון צוות רואה אותה, למרות שאינו מקבל
   את נתוני השיבוצים עצמם — השרת מחשב את המיקום ושולח רק את התוצאה.
   בטופס הרופא יש שדה **"חדר נוכחי"** למנהלים: בחירת חדר מצמידה את הרופא אליו
   ידנית וגוברת על השיבוצים (מסומן בטבלה ב-📌 ובצבע כתום). הקומה נגזרת מהחדר
   שנבחר, ולכן אי אפשר לטעות בה. ניקוי השדה מחזיר את הרופא ללוח המשמרות.
   שימו לב שההצמדה הידנית אינה מתבטלת מעצמה — יש לנקות אותה כשהיא כבר לא נכונה.
4. **שיבוצים** — איזה רופא נמצא באיזה חדר ובאילו שעות. השיבוץ חל בכל יום;
   השלט על הדלת בוחר לבד את הרופא הנכון לפי השעה — אין צורך לגעת בו.
5. **שלטים** — רוב השלטים אינם רשומות אלא נגזרים ממה שכבר קיים:
   - **שלט דלת** — `?room=<מספר חדר>`. לכל חדר יש שלט מוכן ברגע שהחדר נוצר,
     בלי להגדיר דבר. מראה השלט וכיוון המסך נקבעים בטופס החדר עצמו.
   - **מדריך קומה** — `?floor=<מספר>`. לכל קומה שיש בה מחלקות.
   - **שלטים מותאמים** — רק אלה נשמרים כרשומות, כי התוכן שלהם לא נגזר משום
     מקום אחר: `wayfinding` (חצי הכוונה בלובי) ו-`notice` (לוח הודעות).
6. **הודעות** — טקסט שמוצג בתחתית השלטים. אפשר לכוון לכל השלטים, למחלקה או לחדר יחיד,
   עם רמה (מידע / אזהרה / התראה) וחלון זמן.

כל שינוי בממשק הניהול נדחף למסכים **מיידית** (Server-Sent Events), בלי לרענן ובלי לגשת למסך.

### השלט אף פעם לא ריק

בשעות הקבלה השלט מציג בגדול את הרופא שנמצא בחדר **כרגע**.
מחוץ לשעות הקבלה — בערב, בלילה, בסופ"ש — הוא לא מתרוקן, אלא מציג את
**רופאי החדר ושעות הקבלה שלהם** ואת ההופעה הבאה ("מחר 08:00 · ד"ר אבי כהן").
אם לחדר לא שויכו שיבוצים כלל, מוצג צוות המחלקה.
גם מדריך הקומה מציג את שם הרופא של כל חדר ומתי הוא מגיע, ולא רק "פנוי".

### החלפת נתוני ההדגמה

המערכת נוצרת עם מחלקות ורופאים לדוגמה כדי שיהיה מה לראות.
אפשר למחוק אותם אחד-אחד בממשק, או פשוט למחוק את `data/db.json` ולהתחיל מדף חלק.

## התקנה על מסך ליד הדלת / Setting up a screen

1. בממשק → **שלטים** → הוספה, ובוחרים סוג ואת החדר/הקומה.
2. מעתיקים את הכתובת מכרטיס השלט.
3. פותחים אותה בדפדפן של המסך/הטאבלט ולוחצים **F11** למסך מלא.
4. כדאי לכבות במסך את מצב השינה ואת שומר המסך.

אם המסך מאבד חיבור לשרת מופיעה חיווית "אין חיבור" והשלט מנסה להתחבר מחדש לבד;
כשהחיבור חוזר הוא מתעדכן מיד.

### דלתות בלי מסך / Doors that still use paper

פותחים את כתובת השלט בדפדפן ומדפיסים משם (Ctrl+P), או מוסיפים `&print=1`
לכתובת כדי לקבל ישר את גרסת ה-A4. כך אפשר להתחיל בהדרגה: חלק מהדלתות
דיגיטליות וחלק מודפסות מאותה מערכת.

## גיבוי / Backup

כל הנתונים יושבים בקובץ אחד: `data/db.json`.
במסך **הגדרות** יש כפתור "גיבוי עכשיו" שיוצר `data/backup-<תאריך>.json`.
קודי הגישה **לא** נשמרים בקובץ הגיבוי, כדי שאפשר יהיה להעביר אותו בלי לחשוף אותם.
להעברה למחשב אחר — מספיק להעתיק את התיקייה כולה (כולל `MASTER-CODE.txt`).

### API

| Method | Endpoint | |
|---|---|---|
| `GET` | `/api/state` | כל הנתונים לממשק הניהול |
| `GET` | `/api/display/:signId` | מה שהשלט צריך להציג, מוכן לרינדור |
| `GET` | `/api/events` | זרם עדכונים חי (SSE) |
| `GET/POST/PUT/DELETE` | `/api/{departments,rooms,doctors,assignments,signs,messages}[/:id]` | CRUD |
| `POST` | `/api/register` | הרשמת משתמש חדש (ציבורי) — מחזיר קוד אישי פעם אחת |
| `GET/PUT/DELETE` | `/api/users[/:id]` | ניהול משתמשים (מנהלים בלבד) |
| `POST` | `/api/users/:id/code` | הנפקת קוד אישי חדש (קוד גיבוי בלבד) |
| `GET/POST` | `/api/mail` | תיבת הדואר האישית: קריאה ושליחה |
| `GET` | `/api/mail/contacts` | רשימת נמענים (שמות בלבד) |
| `PUT/DELETE` | `/api/mail/:id` | סימון נקרא/בוצע (נמען בלבד), מחיקה חד-צדדית |
| `GET/PUT` | `/api/me` | הפרטים של המשתמש המחובר; עדכון שם וטלפון בלבד |
| `POST` | `/api/me/code` | בחירת קוד אישי חדש (דורש את הקוד הנוכחי) |
| `PUT` | `/api/settings` | שם בית החולים, קודי גישה |
| `POST` | `/api/backup` | יצירת גיבוי |
| `POST` | `/api/auth` | בדיקת קוד כניסה (מחזיר `master: true` לקוד הגיבוי) |

פעולות כתיבה דורשות כותרת `X-Admin-Pin` (קוד יומי או קוד גיבוי).
שינוי של אחד הקודים דורש בנוסף את השדה `masterConfirm` **בגוף הבקשה** עם קוד הגיבוי
(לא בכותרת — כותרת HTTP לא יכולה להכיל תווים מחוץ ל-Latin-1, וקוד שהודבק מטקסט בעברית
עלול לגרור סימני כיווניות בלתי נראים).

כל הקודים עוברים ניקוי לפני השוואה: רווחים וסימני עיצוב בלתי נראים מוסרים,
כך שקוד שהודבק מתנהג כמו קוד שהוקלד.

## הערת אבטחה / Security note

ההגנה כאן היא קוד PIN פשוט, והתקשורת אינה מוצפנת (HTTP). זה מתאים לרשת פנימית סגורה
של בית החולים. אם המערכת אמורה להיות נגישה מחוץ לרשת הפנימית, צריך להוסיף HTTPS
והזדהות אמיתית — ולוודא מול מחלקת ה‑IT/אבטחת מידע של בית החולים לפני חיבור לרשת הארגונית.
